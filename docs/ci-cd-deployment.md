# CI/CD Deployment Guide

This document explains the automated deployment pipeline for Authrim, covering required secrets, how to export them from the setup tool, and the overall deployment flow.

## Overview

Authrim uses a **secrets-based deployment model** to keep sensitive Cloudflare resource identifiers out of the git repository:

- `wrangler.toml` files are **gitignored** and generated at deploy time from config stored in GitHub Secrets.
- `.authrim/` directory (config.json + lock.json) is **gitignored** — these files must never be committed.
- All Cloudflare resource IDs (KV namespace IDs, D1 database IDs) live exclusively in GitHub Secrets.

## Branch Strategy

| Branch    | Target             | Trigger                     |
|-----------|--------------------|-----------------------------|
| `develop` | `test.authrim.com` | Push or PR (if secrets set) |
| `main`    | Production         | Manual (`workflow_dispatch`) |

> **Never commit directly to `main` or `develop`.** Always use feature branches and Pull Requests.

## Required GitHub Secrets

Set these in **Settings → Secrets and variables → Actions** of the repository.

| Secret Name              | Description                                      |
|--------------------------|--------------------------------------------------|
| `CLOUDFLARE_API_TOKEN`   | Cloudflare API token with Workers deploy permission |
| `CLOUDFLARE_ACCOUNT_ID`  | Cloudflare Account ID                            |
| `AUTHRIM_TEST_CONFIG`    | Contents of `.authrim/test/config.json`          |
| `AUTHRIM_TEST_LOCK`      | Contents of `.authrim/test/lock.json`            |

### Cloudflare API Token Permissions

The `CLOUDFLARE_API_TOKEN` requires the following permissions:

- **Workers Scripts**: Edit
- **Workers KV Storage**: Edit
- **D1**: Edit
- **Cloudflare Pages**: Edit (if deploying UI)
- **Account Settings**: Read (for Workers subdomain lookup)

### How to Create the Token

1. Go to [Cloudflare Dashboard](https://dash.cloudflare.com/profile/api-tokens)
2. Click **Create Token** → **Custom token**
3. Add the permissions listed above
4. Scope to your account and the specific zone if applicable
5. Copy the generated token and save it as `CLOUDFLARE_API_TOKEN`

## Exporting Config and Lock as Secrets

After running the Authrim setup tool (`authrim-setup init`), two files are generated locally:

```
.authrim/test/config.json   # Environment configuration
.authrim/test/lock.json     # Provisioned resource IDs (KV, D1, etc.)
```

These files are **gitignored** and must be exported to GitHub Secrets manually.

### Using GitHub CLI (recommended)

```bash
# From the authrim repository root
gh secret set AUTHRIM_TEST_CONFIG < .authrim/test/config.json
gh secret set AUTHRIM_TEST_LOCK   < .authrim/test/lock.json
```

### Using GitHub Web UI

1. Copy the entire contents of `.authrim/test/config.json`
2. Go to **Repository → Settings → Secrets and variables → Actions → New repository secret**
3. Name: `AUTHRIM_TEST_CONFIG`, Value: paste the JSON content
4. Repeat for `.authrim/test/lock.json` → `AUTHRIM_TEST_LOCK`

### After Updating Cloudflare Resources

If you re-run `authrim-setup init` and new KV namespaces or D1 databases are provisioned, update the secrets:

```bash
gh secret set AUTHRIM_TEST_CONFIG < .authrim/test/config.json
gh secret set AUTHRIM_TEST_LOCK   < .authrim/test/lock.json
```

## Deployment Flow

When a push or PR targets the `deploy` branch, the following workflow runs (`.github/workflows/deploy-test.yml`):

```
Push / PR to `deploy`
  │
  ├─ [Guard] Check required secrets are set
  │     If any secret is missing → job is skipped (not failed)
  │
  ├─ pnpm install
  ├─ Build setup package (@authrim/setup)
  │
  ├─ Restore secrets to files:
  │     AUTHRIM_TEST_CONFIG → .authrim/test/config.json
  │     AUTHRIM_TEST_LOCK   → .authrim/test/lock.json
  │
  ├─ scripts/ci-generate-wrangler.mjs
  │     Reads config.json + lock.json
  │     Generates packages/*/wrangler.toml  (gitignored, ephemeral)
  │
  └─ scripts/deploy-with-retry.sh --env=test --api-only
        Uses CLOUDFLARE_API_TOKEN + CLOUDFLARE_ACCOUNT_ID
        Deploys all API workers sequentially
        → test.authrim.com ✅
```

## File Locations Reference

| Path                          | In Git | Source                      |
|-------------------------------|--------|-----------------------------|
| `packages/*/wrangler.toml`    | ❌ No  | Generated by `ci-generate-wrangler.mjs` |
| `.authrim/test/config.json`   | ❌ No  | GitHub Secret `AUTHRIM_TEST_CONFIG` |
| `.authrim/test/lock.json`     | ❌ No  | GitHub Secret `AUTHRIM_TEST_LOCK`   |
| `.authrim-keys/`              | ❌ No  | Local only (crypto keys)    |
| `.github/workflows/deploy-test.yml` | ✅ Yes | Workflow definition    |
| `scripts/ci-generate-wrangler.mjs`  | ✅ Yes | Wrangler generation script |

## Local Development

For local deployment, the standard setup tool flow is used:

```bash
# Deploy from local machine (uses .authrim/test/config.json + lock.json directly)
authrim-setup deploy --env=test

# Or using the deploy script (requires wrangler.toml to already exist)
./scripts/deploy-with-retry.sh --env=test --api-only
```

The `authrim-setup deploy` command automatically generates `wrangler.toml` files from the local config and lock files before deploying, so no manual generation step is needed locally.

## Security Notes

- **Never commit `.authrim/`, `.authrim-keys/`, or `wrangler.toml`** — these paths are gitignored and contain sensitive resource identifiers.
- Secrets passed to `run:` steps are always injected via environment variables (not inline `${{ }}` expansion) to prevent shell injection.
- The deployment job is skipped entirely on forks and when secrets are absent, preventing accidental exposure of secret names via error messages.
- Rotate `CLOUDFLARE_API_TOKEN` regularly and restrict it to the minimum required permissions.
