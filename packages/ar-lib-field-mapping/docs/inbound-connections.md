# Incoming OP / IdP connection mappings

This is the incoming connection contract. It does not use the outgoing Mapping Set facade,
Destination Profiles, consent/release policies, or persistent subject generation. The graph format,
Control Plane repository, compile/activation primitives and `executeTenantMapping` remain shared.

The API owner is ar-management. Routes are:

| Method | Route                                                  | Required permissions                      | Additional gate                                                         |
| ------ | ------------------------------------------------------ | ----------------------------------------- | ----------------------------------------------------------------------- |
| GET    | `/api/admin/identity-mapping/inbound/op/{id}`          | settings:read + external_providers:read   | —                                                                       |
| PUT    | `/api/admin/identity-mapping/inbound/op/{id}`          | settings:write + external_providers:write | external_identity_providers capability; federation.trust.update step-up |
| POST   | `/api/admin/identity-mapping/inbound/op/{id}/preview`  | settings:read + external_providers:read   | —                                                                       |
| GET    | `/api/admin/identity-mapping/inbound/idp/{id}`         | settings:read + saml_providers:read       | —                                                                       |
| PUT    | `/api/admin/identity-mapping/inbound/idp/{id}`         | settings:write + saml_providers:update    | federation.trust.update step-up                                         |
| POST   | `/api/admin/identity-mapping/inbound/idp/{id}/preview` | settings:read + saml_providers:read       | —                                                                       |

Permissions above have the `admin:` prefix. The route/access inventory is
`ar-management/src/admin-route-access.ts`; DTOs are in the API owner's `admin.openapi.yaml`.
The console's generated operation inventory is regenerated by its existing
`scripts/generate-api-operations.mjs`.

GET returns `revision`, `protocol`/receiver `role`, `configured`, `editable`, `sources`, `targets`,
`content`, `providerUpdatedAt`, `enabled` and `legacyMappingPresent`. The document contains no provider
credentials or user records. It reads the bound active version, not an unrelated latest draft.
An existing graph the editor cannot represent losslessly remains inspectable and is not converted.

PUT takes `{revision, sources, rules}`. Each source declares only `{namespace,path,cardinality}`;
types and classifications belong to the server. `rules` uses the explicit graph contract described
in `graph-contract.md`: one unique target and one explicit output, rule-local earlier-step inputs.
The request is bounded to 128 KiB, also subject to the normal Admin body limit. There are at most
100 rules and 100 declared source fields. Existing Control Plane graph/string/transform budgets apply.
`Idempotency-Key` is required, principal/authority/tenant/path/body-bound, 8–128 characters, retained
for 15 minutes. Same-key changed requests conflict; an in-flight request returns 425. A known
replay returns its original result and never restores its binding over a subsequent edit.

## Namespaces and schemas

| Source namespace | Meaning                                                                                                                                          | Supported values                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `oidc.userinfo`  | The existing OIDC receiver's verified/subject-checked userinfo object (including its validated ID-token claims when that is the existing source) | Exact, literal claim names; strings or string arrays. `email_verified` is boolean and can be read, never written. |
| `saml.subject`   | Existing ACS-validated assertion subject                                                                                                         | `nameId` and `nameIdFormat`, single strings                                                                       |
| `saml.attribute` | Existing ACS assertion attributes                                                                                                                | Exact Attribute Name or FriendlyName, strings or string arrays                                                    |

Unmapped incoming fields do not become outputs. A multi-valued source must be explicitly reduced
(e.g. `first` or `join`) to a supported single-string target. A source declared single that receives
an array fails; a multi source may receive a singleton. Names are bounded to 512 characters and
prototype path segments are refused. Dot characters in names do not imply a nested-object read.
Object/number custom source schemas and multi/boolean/number/JSON custom targets are outside this
slice. No implicit stringification of unsupported structured data is performed.

All incoming fields are classified PII by this connection contract. Custom fields cannot be used to
lower that classification; a source reading a more sensitive classification than its destination
is refused. Field references cannot disguise a different read using an ID, type, alias or profile.
Disconnected edges/steps are validated too. Runtime repeats the boundary checks against the tenant's
current custom schema and fails if a configured field becomes unsupported.

`authrim.profile` supports these single-string targets:
`email`, `name`, `given_name`, `family_name`, `middle_name`, `nickname`, `profile`, `picture`, `website`, `gender`, `birthdate`, `zoneinfo`, `locale`.
`authrim.custom_claims` supports active tenant custom claim schemas of string/single cardinality,
with their actual classification. The API excludes protected/colliding names. Identity, tenant,
account, lifecycle, provenance, `sub`, `email_verified`, role and permission fields are not writable.
Persistent identifier generation is refused, including disconnected steps. The remaining existing
bounded attribute transforms use the shared registry, evaluator and tenant hash preparation.
There is no second transform engine.

Preview takes the same draft plus `sample`. OP samples are objects with direct claim-name keys.
IdP samples are objects with `saml.subject` and `saml.attribute` objects keyed by exact field names.
Single-element SAML Attribute arrays are unwrapped by the same helper as ACS.
Use synthetic values such as `sample@example.test`. The response is `{profile,customClaims}` from
the actual evaluator and receiver projection; it issues no session, stores no sample, and runs no
link/JIT/account policy. A missing tenant hash key fails clearly; preview never provisions keys.

## Storage, concurrency and runtime

Each save creates a new tenant-owned catalog, set, version and compiled snapshot using the existing
repository, publishes/compiles/activates it, then compare-and-swaps the provider settings and update
time. Activation scope is `oidc/rp` plus provider ID, or `saml/sp` plus partner entity ID, with
`inboundContract: connection-v1`. The provider pins both set and version. No migration or new Worker binding
is needed. Old shared sets are never edited, so this save has no shared-impact confirmation. Existing
reference scanning counts the new OP binding and preserves pins against deletion/scope/version swaps.
Historical sets remain available under the existing history/maintenance policy.

OP binding: `upstream_providers.provider_quirks.inboundIdentityMapping`.
IdP binding: `identity_providers.config_json.identityMapping`.
Both selectors contain `fieldMappingSetId` and `fieldMappingVersionId`. The SAML selector also retains
`inboundContract: connection-v1`, so a missing activation contract cannot silently select its legacy receiver path. Other settings are preserved;
OP's normal provider update also preserves the database's reserved selector atomically. Mapping
saves return the provider's new timestamp so General -> enable uses the new IdP precondition.
No metadata, keys or advanced settings are added by this slice.

A stale revision or concurrent settings edit returns 409. A failed save keeps the previously bound
graph in use. Known pre-binding failures clean up the new set; ambiguous database outcomes retain
it because the provider may already reference it. Read again before using a new operation key.
Compilation/graph errors do not activate a fallback. Foreign-tenant/wrong-type providers return 404;
foreign graphs, outgoing profiles, invalid IDs/types/classification/operations return 400 at save.
An inactive/invalid configured binding returns a conflict on read and fails at sign-in.

Unconfigured OIDC providers keep the existing `attribute_mapping` behavior without conversion.
Once configured, a graph supplies profile/custom claims alone; stale legacy standard/custom
projections are not mixed back in. The validated provider subject and authentication evidence stay
immutable. A changed email does not inherit `email_verified`; existing provider trust, account linking,
JIT, invitations, required-email and tenant policies still apply. Legacy SAML bindings continue their
existing ACS path; connection-v1 uses the shared strict incoming evaluator/projection within ACS.
For configured OPs the receiver also retains validated upstream claims separately for existing
`idp_claim` JIT policies and raw linked-identity claim storage. Dropping a claim from the mapped
profile cannot bypass a deny policy. Account/profile/custom-claim writes and email trust continue
to use the mapped projection, not those raw claims. Unconfigured legacy behavior is unchanged.

The console uses the existing incoming FlowCanvas/FlowScope/FlowSequence/FlowStepGroup/FlowEndpoint
pattern. Mapping editing lives only in its Mapping node. General and Mapping stay mounted across
node switches, both drafts survive, pending operations prevent conflicting writes, read-only roles
can inspect/preview, and binding-save updates General's IdP timestamp/status without discarding its
draft. No fake test/save/OurDetails components enter the live route.
Successful IdP enable/disable also refreshes Mapping's revision precondition without replacing
either mounted editor or its draft.

The protocol suite reuses the Admin HTTP/SQLite fixture to save, compile and bind connection-v1
graphs, then calls the actual Bridge callback and SAML SP ACS. OIDC uses generated RSA-signed ID
tokens and local OP HTTP responses, with the real client validation, mapper and identity stitching.
It checks the account provisioner's profile/subject/email-trust request and decrypts the actual JIT
plan to inspect custom claims. The account adapter returns pending, so the callback issues its
normal provisioning continuation and no session. Unverified or remapped email cannot become
verified, and the real provider verified-email policy still refuses either case when required.
SAML uses a generated certificate and the existing XML signer with real signature verification,
parser, stored binding and evaluator; mapped claims reach account/custom-claim/linked-identity
persistence and session adapters while the signed NameID stays the identity key. Invalid signatures,
replay, inactive bindings and foreign-tenant bindings prevent further identity/session effects;
OIDC also refuses malformed binding settings. Only ancillary policy/storage/account/session adapters
are controlled. No real network, accounts, fixture secrets or new test configuration are needed.
